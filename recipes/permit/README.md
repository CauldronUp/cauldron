# permit

Emulates the Permit.io projects API for local development and tests.

**7 conformance cases, 2 checked against the live API on 2026-09-13.**

Read from the OpenAPI document Permit serves without a credential at [`api.permit.io/openapi.json`](https://api.permit.io/openapi.json), and struck live on 2026-09-13 with no credential and with a deliberately invalid one.

## What this Recipe found

**The document declares two responses and neither is the one you get first.** `GET /v2/projects` lists `200` and `422` — a success and a validation error — on an API that answers 401 to every request arriving without a token. The only failure in the contract is the one a well-formed request cannot cause.

**The failure mentions a login cookie.**

```
(no header)      401 {"detail":"An authorization header or login cookie is required"}
Bearer notreal   401 {"detail":"Invalid credentials"}
```

A browser session, named to a caller that has no browser. The two sentences share one key and nothing else, so a client cannot branch on anything but the text.

**A regular expression that anchors nothing.** `urn_namespace` is declared `pattern: "[a-z0-9-]{2,}"`. There is no `^` and no `$`, and a JSON Schema pattern is a *search* rather than a match — so `Not A Namespace At All!` satisfies it on the strength of the `ot` in the middle. The field that exists to constrain a namespace constrains nothing a caller would get wrong.

**Every property carries a title that is its own name.** `"title": "Urn Namespace"` on `urn_namespace`, `"title": "Id"` on `id`, `"title": "Created At"` on `created_at` — the field name with its underscores turned into spaces and each word capitalised, generated by the framework and shipped in the published contract. Ten properties, ten titles, no information.

**And the success schema's own title is a sentence about the operation.** `"title": "Response List Projects V2 Projects Get"` — the handler name and the path, Title Cased, as the name of the response type. A generated client makes a class out of it.

**Two identifiers, and the one you query by is not the primary one.** `id` is a uuid; `key` is "a URL-friendly name of the project (i.e: slug). You will be able to query later by this key". The field that addresses a project is the slug, and the uuid never appears in a path.

**The listing pages and says nothing about the pages.** `page` and `per_page` are declared parameters and the response is a bare array: no total, no next, no count. Asking for a page past the end is how a caller learns there is no page past the end.

## Modelling limits

- **One route.** Listing projects. Environments, resources, roles, tenants, users, condition sets, the policy-decision surface and the audit log are 163 more paths.
- **The 422 is not modelled.** It is the one failure the document declares, and it needs a malformed request to provoke; nothing this Recipe does sends one.
- **The unanchored pattern is quoted, not enforced.** Cauldron serves fixture values and does not validate them against the description, so the finding is what the document permits rather than what the sandbox accepts.
- **Nothing is mapped in detection.** Permit.io is reached through its PDP sidecar and its language SDKs, which are pointed at a locally-running decision point rather than at this management API — so a dependency names the sidecar's client and never this host. Checked 2026-09-13.
